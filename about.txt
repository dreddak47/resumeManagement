In my main full time role, I entered into medusa (Documents/medusa/service) - a server side event driven service . This service basically get events/ entity(different user types exists in how emails/domain exist) updates from all service/clients . This is the briefest I can be. So basically we process all events / entities . Events come - validated against their final schemas, processing, then use a maintained pipeline to S3 bucket for storage of events in files, move around to 3rd party integrations. Entity updates are validated along their schemas, processed , and then moved around to DB/ or 3rd party integrations .  

3rd party integrations exist like moengage/pendo which are used by different teams to analyse events/entities.
 Medusa moves events and entities updates to 3rd integration through one more service - chidori. Basically medusa moves all events/entities update to different SQS based on different integration types, which is then polled by chidori. It process, validates, handles SQS management, and calls API to third party integrations

Within medusa, we manage 2 more mini services - one is chidori(Documents/medusa/chidori) and one is medusaReports(Documents/medusa/medusareports) . medusaReports is the main service which basically handles core DB side, it handles Schema management etc . Medusa reports also do many of the cron jobs , which handle certain maintainence/reporting kind of jobs. One of the example is running a script every day to see last usage of events through Athena queries.

All the main user/events models, different kind of models which were used by so many services to interact with medusa were maintained in 2 libraries medusacommons(Documents/medusa/commons)  and medusa client(Documents/medusa/interface) .

There is a different service which is a part of medusa: medusa-athena-scripts (Documents/suite-scripts/k8s-scripts). Basically we maintain certain scripts (Java) . These are kind of ETL pipelines, which properly maintains events in S3, doing jobs like splitting events, compacting events etc. We also handle entity snapshots From DB to S3. All of this helped multiple teams to view customer/ events related data on Athena easily. The scripts used to run on airflow through DAG.
